# 可观测数据的集群归属

指标、日志、链路页沿用原有界面，集群列表受顶栏环境限制。数据源先匹配环境，再匹配 `options.cluster_id` 或 `options.cluster_name`；同环境存在多个未绑定的同类数据源时提示配置歧义，不任意选择。

独立数据源建议设置 `options.cluster_id`，值为平台 `/clusters` 返回的 ID。同环境仅有一个集群且仅有一个同类数据源时兼容现有配置。

多个集群共享 Loki 时，每个采集端的输出都应带 `cluster=<平台集群名>` 标签。页面查询自动加入该标签，不返回未标记的数据。其他标签名可通过数据源 `options.cluster_label` 设置；原有日志选择器默认 `{job="fluent-bit"}`，可通过 `options.log_selector` 配置。历史日志在补标签之前不会自动变更。

多个集群共享 Jaeger/Tempo 时，在 OpenTelemetry 资源属性中设置 `k8s.cluster.name=<平台集群名>`，例如应用的 `OTEL_RESOURCE_ATTRIBUTES`。页面搜索自动附带此标签；详情保留并检查 Jaeger process tags 中的资源属性。不同标签名可通过数据源 `options.cluster_label` 设置。尚未接入业务埋点时显示空结果。

指标卡和历史图使用真实 Prometheus query_range；节点指标通过所选集群节点的内部 IP:9100 限定，工作负载通过 namespace/pod 与节点关联。CPU/内存按命名空间或应用筛选时表示其占集群可分配资源的比例。网络与磁盘始终表示所选集群节点。未采集的序列显示“—”，不生成补值。Pod 重启显示当前累计次数，不能把累计曲线各点相加。

总览即时 CPU/内存来自 metrics-server 的节点使用率均值；历史图来自 node-exporter，CPU 为 5 分钟速率，内存按物理总量加权，因此两者不要求数值相等。页面说明数据来源与统计口径。

日志默认读取最近最多 500 条，KQL 筛选这一批结果。结构化消息、HTTP 状态、耗时与常见故障展示可读摘要；展开行保留完整原文。链路 RED 与排行明确为检索样本统计，不冒充全量业务指标。

通知渠道从后端读取并保存；未配置时保留飞书、钉钉、企业微信、邮件的配置卡。测试发送仅在用户点击后调用真实接口，结果由接口返回；不会自动向外发送测试消息。
